## 核心思想

客户端本身不包含游戏运行所需的全部逻辑——**缺失的那部分在服务端**。所谓"复活"，就是依据客户端留下的线索，把这部分服务端逻辑补回来。

> **先跑通登录。** 登录跑通即意味着客户端已成功连上自制服务端，项目就成功了一半。

记忆口诀：**先用探针把登录状态机跑明白，再用最低层的重定向把流量骗到本地，最后按依赖顺序把协议补全。**

## 三条总体思路

| 方案 | 思路 | 优点 | 缺点 / 适合场景 |
| --- | --- | --- | --- |
| **复原服务端**（默认通用解） | 重写能配套运行的服务端，让客户端"以为"仍在官方服务器上 | 通用性最强；可保留多人功能；对客户端改动最少 | 启动链复杂、需逐步补协议；适合大多数场景 |
| **改造客户端** | 注入代码，把原发给服务端的请求在客户端内部处理，单机化 | 无需服务端；有机会做成点开即玩的单机版 | 需深入改已编译代码，受引擎/混淆影响大；适合代码较易读易改的客户端 |
| **重做客户端** | 只提取资源（模型 / 动画 / 场景）重做展示工具 | 难度最低；不依赖原协议 | 无法保留完整玩法；适合只想还原角色 / 剧情 / 场景 |

## 方法论主线（八阶段）

1. **战略选型** — 复原服务端 / 改造客户端 / 重做客户端。
2. **静态侦察** — 文件完整性与热更；三类线索：配置表、数据包协议、代码与热更模块；登录架构（直连 vs 中台 / SDK）。
3. **观测工具** — 注入框架 + 引擎与热更 VM 日志统一落文件 + 错误探针 + 崩溃兜底。
4. **状态机建模** — 把登录全链路每一跳建模为 `触发 → C2S → S2C → 下一步`。
5. **分层拦截** — DNS / 寻址 → 传输 / TLS → SDK / 中台 → 业务协议，自底向上，改动面最小化。
6. **逐层补回包** — 从登录链最上游往下逐跳应答，一次只补一个，两侧日志比对。
7. **时序与推送** — 依赖某次初始化的数据，必须在触发它的请求应答之前推送。
8. **持续优化** — 错误驱动、功能生效验证、一键闭环、版本适配器与门控。

## 五条铁律

1. **先静态再动态、先观测后改动** — 没有日志 / 探针前动手 = 盲修。
2. **分层拦截，自底向上** — 能改寻址就不碰业务，能伪造协议就不改客户端。
3. **一次只补一个** — 让每次改动与日志一一对应，出错时对照客户端与服务端两侧日志。
4. **时序即接口** — 推送顺序必须匹配客户端初始化顺序。
5. **版本门控 + 证据分级** — 每个 hook / patch 三重校验（模块名 + SHA-256 + 字节签名）；结论标注证据级别。

## 拦截层决策矩阵

按"改动面最小 / 通用性最高"排序，逐层尝试：

| 层 | 手段 | 何时用 | 代价 |
| --- | --- | --- | --- |
| DNS / 寻址 | 注入取地址函数，域名 → `127.0.0.1` | 地址来自域名、端口可覆盖 | 最低 |
| 传输 / TLS | HTTPS 降级、阻断证书校验、本地 CA、TLS 代理 | 原协议是 TLS 且无本地证书 | 中 |
| SDK / 中台 | inline hook 登录函数，伪造成功回调 | 平台登录无法离线 | 中高 |
| 业务协议 | 服务端按真实 wire format 应答 | 始终需要 | 高（但必须） |

## 快速开始

在本机全局配置 `~/.config/opencode/opencode.json` 中注册本目录：

```json
{ "$schema": "https://opencode.ai/config.json", "skills": { "paths": ["E:/AI/Skills"] } }
```

保存后退出并重启 opencode 生效。Agent 会在遇到相关任务时按 `SKILL.md` 的 `description` 自动触发匹配。

## 适用与边界

| | 说明 |
| --- | --- |
| **适用** | 客户端能启动但卡在登录；服务已下线但有可运行客户端；私服、离线复原、协议研究 |
| **不适用** | 客户端被完全加密且无任何可观测点；目标是绕过合法授权 / 付费墙 |
| **需具体分析** | 加密加壳、特殊架构等场景不在方法论覆盖范围内 |

> **免责声明**：本项目仅供游戏开发的学习与研究。请勿用于仍在运营中的游戏。

## 贡献

欢迎补充新的 Skill 或修正方法论。每个 Skill 为一个目录：

```
<skill-name>/
├── SKILL.md        # 必需，YAML frontmatter（name + description）+ 正文
├── README.md       # 可选，面向人的介绍
└── reference/       # 可选，按需加载的参考文档
```

`SKILL.md` frontmatter 的 `name` 必须与目录名一致（小写连字符）；`description` 需同时说明"做什么"和"何时触发"，并前置触发关键词。提交 PR 前请确保内容仍属于「网游离线化」范畴。
