# Game Offliner Skill

> 关服 / 离线网游复活相关的 Agent Skill 仓库。本仓库**只收录与"网游离线化方法论"直接相关的 Skill**。

这里沉淀的是一套**如何让已关服、服务不可达的网游客户端重新跑起来**的通用方法论，并以 Agent Skill 的形式提供给 AI 使用，使其在其他项目里也能按同一套流程推进，少走弯路、省下反复试错的 Token。

## 方法论一句话

客户端本身不包含游戏运行所需的全部逻辑——**缺失的那部分在服务端**。所谓"复活"，就是依据客户端留下的线索，把这部分服务端逻辑补回来。

优先目标永远是**先跑通登录**：登录跑通即意味着客户端已成功连上自制服务端，项目就成功了一半。

## 三条总体思路

| 方案 | 思路 | 优点 | 缺点 / 适合 |
|---|---|---|---|
| **复原服务端**（默认通用解） | 重写能配套运行的服务端，让客户端"以为"仍在官方服务器上 | 通用性最强；可保留多人功能；对客户端改动最少 | 启动链复杂、需逐步补协议；适合大多数场景 |
| **改造客户端** | 注入代码，把原发给服务端的请求在客户端内部处理，单机化 | 无需服务端；有机会做成点开即玩的单机版 | 需深入改已编译代码，受引擎/混淆影响大；适合代码较易读易改的客户端 |
| **重做客户端** | 只提取资源（模型/动画/场景）重做展示工具 | 难度最低；不依赖原协议 | 无法保留完整玩法；适合只想还原角色/剧情/场景 |

## 方法论主线（八阶段）

1. **战略选型** — 复原服务端 / 改造客户端 / 重做客户端。
2. **静态侦察** — 文件完整性与热更；三类线索：配置表、数据包协议、代码与热更模块；登录架构（直连 vs 中台/SDK）。
3. **观测工具** — 注入框架 + 引擎与热更 VM 日志统一落文件 + 错误探针 + 崩溃兜底。
4. **状态机建模** — 把登录全链路每一跳建模为 `触发 → C2S → S2C → 下一步`。
5. **分层拦截** — DNS/寻址 → 传输/TLS → SDK/中台 → 业务协议，自底向上，改动面最小化。
6. **逐层补回包** — 从登录链最上游往下逐跳应答，一次只补一个，两侧日志比对。
7. **时序与推送** — 依赖某次初始化的数据，必须在触发它的请求应答之前推送。
8. **持续优化** — 错误驱动、功能生效验证、一键闭环、版本适配器与门控。

配套的**五条铁律**：先静态再动态、先观测后改动；分层拦截自底向上；一次只补一个；时序即接口；版本门控 + 证据分级。

一句话记忆：**先用探针把登录状态机跑明白，再用最低层的重定向把流量骗到本地，最后按依赖顺序把协议补全。**

## 仓库结构

```
.
├── README.md                     # 本文件：方法论总览
└── offline-login-revival/         # 核心 Skill
    ├── SKILL.md                  # 入口：战略选型、前提与线索、铁律、八阶段、决策矩阵、坑、DoD
    ├── README.md                 # 技能简介
    └── reference/
        ├── playbook.md           # P0–P7 每阶段：目标 / 动作 / 验收 / 检查清单
        └── templates.md          # 注入器、hook 门控、配置、伪造响应、协议表、时序契约、一键脚本、版本适配器
```

后续若新增 Skill，也必须是本方法论在某类引擎 / 传输 / 平台上的具体化。

## 适用与边界

- **适用**：客户端能启动但卡在登录；服务已下线但有可运行客户端；私服、离线复原、协议研究。
- **不适用**：客户端被完全加密且无任何可观测点；目标是绕过合法授权 / 付费墙。
- **另需具体分析**：加密加壳、特殊架构等场景不在方法论覆盖范围内。

> 仅供游戏开发的学习与研究。请勿用于仍在运营中的游戏。

## 使用方式（opencode）

在本机全局配置 `~/.config/opencode/opencode.json` 中注册本目录：

```json
{ "$schema": "https://opencode.ai/config.json", "skills": { "paths": ["E:/AI/Skills"] } }
```

保存后退出并重启 opencode 生效。Agent 会在遇到相关任务时按 `SKILL.md` 的 `description` 触发匹配。

## Skill 格式

每个 Skill 为一个目录：

```
<skill-name>/
├── SKILL.md        # 必需，YAML frontmatter（name + description）+ 正文
├── README.md       # 可选，面向人的介绍
└── reference/       # 可选，按需加载的参考文档
```

`SKILL.md` frontmatter 的 `name` 必须与目录名一致（小写连字符）；`description` 需同时说明"做什么"和"何时触发"，并前置触发关键词。
