# offline-login-revival

> Agent Skill：把已关服 / 服务不可达的联网客户端，通过自制本地服务端重新跑通登录，并可持续迭代、多版本复用。

一套与引擎、语言、传输协议无关的**离线登录复原方法论**。核心思路：客户端不包含运行所需全部逻辑，缺失部分在服务端；"复活"就是依据客户端留下的线索，把这部分服务端逻辑补回来。优先目标是先跑通登录——登录跑通即意味着客户端已连上自制服务端。

## 方法主线

1. **战略选型** — 复原服务端（默认）/ 改造客户端 / 重做客户端。
2. **静态侦察** — 文件完整性与热更；三类线索：配置表、数据包协议、代码与热更模块；登录架构（直连 vs 中台/SDK）。
3. **观测工具** — 注入框架 + 引擎与 VM 日志统一落文件 + 错误探针 + 崩溃兜底。
4. **状态机建模** — 登录全链路每一跳的 `触发 → C2S → S2C → 下一步`。
5. **分层拦截** — DNS/寻址 → 传输/TLS → SDK/中台 → 业务协议，自底向上、改动最小化。
6. **逐层补回包** — 从最上游往下，一次只补一个，两侧日志比对。
7. **时序与推送** — 依赖某次初始化的数据，必须在触发它的请求应答之前推送。
8. **持续优化** — 错误驱动、功能生效验证、一键闭环、版本适配器与门控。

## 五条铁律

先静态再动态、先观测后改动；分层拦截自底向上；一次只补一个；时序即接口；版本门控 + 证据分级。

## 适用 / 不适用

- 适用：客户端能启动但卡在登录；服务已下线但有可运行客户端；私服 / 离线复原 / 协议研究。
- 不适用：客户端被完全加密且无任何可观测点；目标是绕过合法授权 / 付费墙。

> 仅供游戏开发的学习与研究。请勿用于仍在运营的游戏。

## 安装（opencode）

该 Skill 目录不是默认扫描位置，需在 `~/.config/opencode/opencode.json` 中注册：

```json
{ "$schema": "https://opencode.ai/config.json", "skills": { "paths": ["E:/AI/Skills"] } }
```

保存后退出并重启 opencode 生效。

> 在**另一个项目**中使用、以及每个阶段可直接复制的指令，见仓库根目录的 [USAGE.md](../USAGE.md)。

## 参考实现

`blueoath-revival` 类项目：C++ x86 注入 Payload + `getaddrinfo`/libcurl/UnityTLS 运行时 hook + SDK 登录伪造 + .NET 本地服务端（HTTP 引导 + KCP/UDP 游戏登录 + protobuf）。可作阶段模板，但请勿直接复制服别常量。
